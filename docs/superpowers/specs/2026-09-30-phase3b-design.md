# Phase 3B — Everyday training design
Date: 2026-09-30
Authorization: user approved direction and explicitly authorizes implementation, acceptance and deployment after this document self-review. No further approval gate unless destructive history changes or conflicting personal-data semantics arise.

## Visible experience
Aufgabenbank landing never renders question cards. It contains exactly four filter dimensions (knowledge, question type, module, year), dynamic module quick tabs with Alle default, matched count, Training starten, and two compact clickable statistics sections below. All counts derive from current production inventory and classifications. Unknown questions remain in the unfiltered pool. Machine suggestions are usable with a light automatic label; unknown alone is not a mandatory review task.
Fehlertraining landing has four cards only: Stufe 1, Stufe 2, Stufe 3, Gemeistert. No module/year/topic groups. Each offers count and Jetzt üben. Compact Modultest year dropdown remains unchanged.

## Separate training domain
TrainingDefinition canonicalizes/deduplicates/sorts knowledgeTopicIds, questionTypeIds, moduleIds, examIds; stable collision-free serialized key identifies identical filters (equivalent hash/key). TrainingProgress stores current run reference separately from ModuleProgress. TrainingRun freezes question_ids and per-question source/crop/answer/U-solution snapshots, current question, drafts, formal result pointers and revision. Questions are referenced by original ID; snapshots protect provenance, not a second question bank.
Bank same key resumes existing run, even after inventory/classifications change. Show explicit inventory-changed notice and offer new run. Training neu starten creates a new run using current matching pool, retaining prior runs, all attempts, notes and wrong state. Stage card start snapshots latest stage IDs every time; refresh/resume URL restores that specific run. Within run, promotions/demotions never reorder membership; IDs unique. Removed questions are excluded from new runs; existing run retains its historical source snapshot. No silent official-source rebinding.
Training formal attempts carry training_run_id and original exam/module/question identity; do not populate or reset ModuleProgress. Training drafts are stored by run+question rather than ordinary LearningSession. Shared Practice component consumes callbacks, so notes, unsure, reveal-only, attempts and assessment semantics remain consistent. Restart only current training, no destructive cleanup. Navigation and saves guard stale revisions and in-flight edits.
Training entities are local IndexedDB stores and included in backup/import. No hosted sync activation; large snapshots are not silently stuffed into existing small cloud envelopes. Existing Firebase provider remains untouched except any strictly necessary backwards-compatible wrong-state validation.

## Four-stage wrong history
Effective formal results use current eligibility, stable result identities and assessment times. Incorrect or partial -> stage 1. Each later formal correct -> 2 -> 3 -> mastered. Mastered remains discoverable in history, never auto-deleted. Correct answers before any wrong do not create a wrong-training item. Solution viewing creates no effective result. Manual removal records a dismissal watermark; it does not delete history/notes/progress/classification. New wrong after removal reactivates stage 1. Old hidden wrong items become stage 3, not mastered.
Versioned migration preserves each old record as an audit snapshot plus cutover effective-result identities. Existing active streak 0 ->1, streak1 ->2, recovered >=2 ->3; current manual dismissal stays removed. Replay old effective results up to cutover with a maximum of stage3, then apply post-cutover formal results normally; revoked test/attempt contributions must be removed on every reconciliation. This prevents historical third correct answers from skipping the requested final new review. Legacy dismissed-result watermarks retained. Idempotent migration; old attempts, notes and test records never rewritten. If all wrong contributions disappear, no stage card count; never manufacture an error to preserve a count.

## Classification correction
Reusable default-collapsed Klassifikation bearbeiten directly below QuestionNoteEditor in free learning and training. Dynamic knowledge multi-select and primary/secondary type controls; save uses source-bound human_confirmed + locked overlay. No topic/type/year/module enumeration in React. Review queue contains actual conflicts, source changes after human lock, explicitly unclassifiable cases and proposed taxonomy nodes, not every machine suggestion or missing text.
